# Task Manager Replacement Goals and Acceptance

English | [简体中文](ROADMAP.zh-CN.md)

The goal is to cover practical Windows Task Manager workflows, add verifiable device information, and improve responsiveness and updates. Implemented features, partial verification, and complete acceptance are recorded separately. Adding features does not establish complete Task Manager replacement or support for every device.

v0.3 builds on v0.2.1 with stable name sorting, background process icons and menus, typed queries, a ports page, native CPU topology and power information, on-demand offline Authenticode checks, application grouping, and PowerShell download/install scripts. Current v0.3 results are **118 library tests passed, 2 ignored by default**, plus **36 source-level GUI tests passed**, for **154 tests passed in total**. The installation script has **29 self-tests**, run separately under PS5.1 and PS7. The optimized build passed 33/33 native QA checks on this host; release artifact verification and a real v0.3 public MSI installation/upgrade remain pending. This document does not yet mark v0.3 as released or installed.

v0.2.1 fixed extended-path compatibility in Windows Installer command lines. A real installation and automatic launch using the corrected helper passed, as did an upgrade from the installed public v0.2.0 release using the public v0.2.1 MSI. Existing v0.2.0 users must install the corrected MSI once; downloading a new package alone does not repair the old helper. The complete update flow starting with automatic discovery of a newer release still has a verification gap.

A–Z ordering uses the same Unicode lowercase lexicographic rule throughout, not locale-specific collation. Equal names have a stable PID/birth-identity order. The sorting cache reuses the order, never stale process metrics. The UI labels application-group GPU values as the maximum member value; they must not be interpreted as total group GPU load.

The PowerShell script tries official sources first, then bounded sequential fallbacks after short timeouts; it does not benchmark or race mirrors in parallel. Mirrors receive public asset URLs only and cannot supply trusted metadata or checksum files. Downloads use random private directories, size limits, complete SHA-256 validation, and a commit within the same directory. A read lock prevents writing/deleting the installer before installation. The script does not automatically terminate user processes or change execution policy, global proxies, system certificates, or firewall settings. See [installation instructions](docs/installation.md).

File signature verification is triggered by an explicit action on the selected object, not repeatedly run across every process. The ability to inspect other files' signatures does not mean SystemMonitorX release packages have been certificate-signed.

## Performance Acceptance Method

The optimized v0.3 build passed **33/33 native QA checks** on this host, including real icon loading, both context menus, and exact PID navigation, with **994 real processes**. Across **230 individual keystrokes**, keyboard dispatch/filter CPU time was p50 **4.1861 ms**, p95 **5.846 ms**, and max **10.5439 ms**. Across **30 renders**, `render_frame` CPU time was p95 **5.326 ms** and max **5.6907 ms**. These measurements include test-observation overhead, exclude GPU presentation latency, and are not an official Task Manager comparison. They apply to this device and test scope; they do not establish performance across all hardware or workloads.

Existing local v0.2.0 release responsiveness measurements and their scope/timing details are documented in [README.md](README.md). v0.3 implements name-order reuse, background icon loading, and deferred hidden-page models. Improvements to actual responsiveness, application CPU, or memory must be measured again with the final artifacts under matching conditions; code structure alone does not establish them.

Record Windows/drivers, device categories, process count, refresh interval, collection p50/p95/max, application CPU/working set, duration, and stress scenarios. The native UI response tool measures CPU time for keyboard dispatch/filtering and one `render_frame`, excluding PNG encoding and sampling intervals. It does not measure actual GPU presentation latency or divide a whole query batch by its character count and present that as per-keystroke timing.

The 10,000-row model stress dataset is explicitly synthetic and is not evidence of that many real processes. Comparisons with official Task Manager require the same device/load, matching sampling intervals, comparable features, and ordinary, peak, and long-running scenarios. Retain reproduction evidence for stalls and remeasure after fixes. Broad claims of being faster in every case or never stalling are not supported.

## Compatibility and Replacement Gaps Kept Open

- Complete affinity across processor groups; protected/other-user processes and advanced diagnostics; per-user process expansion and multiple-user/remote-session checks.
- All logon startup sources, scheduled tasks, UWP/packaged applications, and measured startup impact; real service dependencies, timeouts, and privilege variations.
- Application-group checks for multiple windows, short-lived members, and changing groups; true per-engine group GPU aggregation, which cannot be replaced by a maximum member value.
- AMD/Intel vendor sensors, universal support for temperature/fan/power devices, and more GPU/driver combinations; the D3D12 UI renderer remains unimplemented.
- Stable public reading of a selected process's current directory; more local catalog/certificate-policy cases, revocation-verification scope, and certificate-signed project distribution.
- Owned ETW bytes/loss per protocol, external/long-running traffic, Windows schema differences, coverage-gap handling, and long-term network history; short-lived port/connection objects and permission cases.
- The complete update flow from automatic discovery of a newer release, MSI cancellation/failure recovery, portable-to-installed transitions, multiple windows, and different Windows/multiple-user environments.
- Long-running performance/memory checks, comparable official Task Manager benchmarks, complete keyboard operation, screen readers/accessibility, DPI/multiple displays, sleep/resume, and window-state regression.

When permissions, drivers, certificate caches, or system interfaces do not provide data, retain the source, error, and unavailability reason. Do not infer capabilities from missing values or device names.
